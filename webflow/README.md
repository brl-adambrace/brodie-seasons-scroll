## CMS fields (per season)

Name (= card title) · Season label · Subheadline · Pill text (fill ONLY on the current season — it shows the pill and makes that season start centred) · CTA label · CTA link · Accent colour (hex) · CTA text colour (hex) · Photo · Season badge · Order (1 = leftmost).

Colours are plain-text hex because the API can't bind a Color field to text or to an attribute. The card carries two hidden text blocks (`.ssc-card__meta-accent`, `.ssc-card__meta-cta`) bound to those fields; the footer script reads them and sets `--accent` / `--cta-text` on the card. If you'd rather have colour pickers, add Color fields and bind them in the Designer's Style panel (subheadline text colour, CTA background, pill dot background, CTA text colour) — the script leaves the CSS-variable path in place as a fallback.

## Moving the section to a real page

Copy the `section.ssc` element in the Designer and paste it on the target page, then copy `head.html` into that page's head code and `footer.html` into its footer code (or move both to site-wide custom code). The section pins with ScrollTrigger, so its parent must have no CSS transform. The Designer canvas shows the four slots stacked at the centre — that's expected; positions and the scroll animation only run on the published page.

## Ways to Play (added 15 Sep 2026)

Third section on the page (`section.wyp`, after `section.dv`), from Figma node 5448-12751. Left column: eyebrow, title, subtitle, "Find Your Game" CTA. Right column: a three-item accordion (Start A Team, Join A Team, Drop-In Run; all closed on load, one open at a time). Static native elements — every text and button is editable in the Designer/Editor; duplicate a `.wyp-item` to add another way to play (adding the `wyp-open` class to an item makes it open by default).

**Video backdrop (real clip since 16 Sep 2026):** `.wyp-media` fills the section; inside it `.wyp-video-wrap` is `position:sticky; top:0; height:100vh`, so the video always fills the viewport while the section grows with the open accordion. Layers inside the wrap, back to front: `img.wyp-poster` (lazy, decorative; the Webflow Image element with asset `ways-to-play-poster.jpg` = the frame at 8.25s, a 1v1 under the arena lights, chosen because frame 0 is black while the lights come up), `video.wyp-video` (no `<source>` children, `preload="none"`, `muted loop playsinline`), `.wyp-scrim` (rgba(0,0,0,.45)). The clip itself is Adam's `ways-to-play.mp4` (1920×1080, 17.2s, 24fps, no audio; the 16 MB master is re-encoded with AVFoundation, moov atom up front) hosted in the Webflow asset library in four encodes, referenced by data attributes on the `<video>`:

| attribute | file | size |
| --- | --- | --- |
| `data-src` | `ways-to-play-1080.mp4` (H.264 3.2 Mbps) | 7.0 MB |
| `data-src-sm` | `ways-to-play-720.mp4` (H.264 1.5 Mbps) | 3.4 MB |
| `data-src-hevc` | `ways-to-play-1080-hevc.mp4` (HEVC 1.8 Mbps) | 4.0 MB |
| `data-src-sm-hevc` | `ways-to-play-720-hevc.mp4` (HEVC 0.9 Mbps) | 2.0 MB |

`data-start="8.25"` is the poster's timestamp. **Loading (homepage-grade):** nothing video-related downloads at page load. After `window.load`, an IntersectionObserver (rootMargin 50%) waits for the section to come within half a viewport, then the footer script picks the encode (`-sm` on ≤767px; HEVC when `canPlayType` says "probably", i.e. Safari, Chrome/Edge with hardware decode), `fetch`es it in full (the CDN sends `access-control-allow-origin: *`), hands the blob to the `<video>`, seeks to `data-start` and, once that frame is decoded, cross-fades the video over the identical poster frame (`.wyp-video-on`, .8s), then starts playback 750ms later. If `fetch` is unavailable or fails it falls back to a native `src` + `canplaythrough`. The video pauses when the section leaves the viewport and resumes when it returns. Visitors with `prefers-reduced-motion: reduce` or Save-Data (or a 2G connection) get the poster only, with the play button as an opt-in.

**Pause/play control:** created by the footer script, not in the Designer: `div.wyp-ctl-bar` (a zero-height `position:sticky; bottom:24px` bar appended to the section, so it stays in the viewport corner above the content while the section is on screen) › `button.wyp-toggle` (44px frosted circle, 40px on phones; `aria-label`/`aria-pressed` swap between "Pause background video" and "Play background video"; state class `wyp-paused` on the section swaps the icons). It sits **bottom-left**: the site's Intercom launcher owns the bottom-right corner on every breakpoint and sat on top of the first version. It appears (`wyp-ctl`) as soon as the video starts downloading (pressing it then parks the clip on the poster frame instead of playing), and immediately in the reduced-motion/data-saver case. If the browser refuses autoplay (iOS Low Power Mode), the control flips to the play glyph so the visitor can start it by hand.

**Replacing the clip later:** upload new encodes to the asset library (see the encode recipe in the repo history: AVAssetWriter, H.264 High / HEVC Main, ~3.2 / 1.5 / 1.8 / 0.9 Mbps), then on the `<video>` element edit the four `data-src*` attributes (any HEVC attribute may be removed; the script falls back to H.264), swap the poster Image's asset to the matching frame and set `data-start` to that frame's time in seconds. Keep the poster frame and start time in sync or the cross-fade will jump.

**Content (final copy from Adam, 16 Sep 2026):** all three accordions start closed (no `wyp-open` class on any item). Start A Team → Become a Captain `https://athletes.brodierec.com/registrations/new/captain/league-details`, Learn More `https://www.brodierec.com/start-a-team`. Join A Team (two paragraphs) → Join a Team `https://athletes.brodierec.com/registrations/new/ways-to-play`, Learn More `https://www.brodierec.com/join-a-team`. Sources: `waystoplay-static.css`, `waystoplay-head.html`, `waystoplay-footer.html`, `waystoplay-prototype.html`. Page code is minified with terser by `build-page-code.mjs` (run `npm install` once). Adam's homepage order: Nav · Hero (unchanged) · **Seasons** · **Divisions carousel** (old `Section_Divisions` removed) · Brodie Experience · News collection · **Ways to Play** · Locations · Stat line (`Section_ImpactNumbers`) · Footer. The stories marquee and the FAQ were not in his list and were left in place (stories before Locations, FAQ before Footer) pending his call. Homepage id `6921d2c2bd3b56136200df25`.

**Code delivery = registered hosted scripts (site convention).** `build-hosted.mjs` bundles each section's behaviour CSS (injected into `<head>` immediately) and JS (run at DOMContentLoaded) into `dist/hosted/<name>-<version>.js` plus `manifest.json` (md5 for the asset upload, sha384 for the registration). Versions live in `hosted-versions.json`. Current: `seasonsScroll` 1.0.0 (asset `6aac48916cf051fab72a3169`), `divisionsCarousel` 1.0.0 (`6aac4891c76f3acb63acec21`), `waysToPlay` 1.0.0 (`6aac4891c76f3acb63acec37`); all three applied in the **header** of Home and of `/seasons-scroll`, whose inline page code was retired. The seasons script reuses the site's global GSAP 3.15 + ScrollTrigger and only loads cdnjs when GSAP is missing. **To ship a change:** bump the version in `hosted-versions.json` → `node build-hosted.mjs` → `data_assets_tool create_asset` (file_hash = md5) + curl multipart to S3 → `register_hosted_script` with the new version + integrity → `add_page_script` on each page with the new version (it replaces the old one). Page-level `dist/page-head.html` / `page-footer.html` are frozen at the last version that fit the 10,000-character cap and are kept only for reference; `build-page-code.mjs` now exits with a warning once the code outgrows the cap.

**Components.** Webflow components cannot contain a live CMS Collection List, so only Ways to Play became a component: `Section_WaysToPlay` id `67f73811-8ccf-4dea-eb73-5e23840f2ba0` (group Sections; instance on Home `c00641d9-87c6-ea86-55a0-4264acb1c398`, instance on the prototype page replaced the original section). The Seasons (`section.ssc`) and Divisions (`section.dv`) sections stay plain elements and are copied to Home by Designer copy/paste (select the section in the Navigator on `/seasons-scroll`, ⌘C, open Home, select the Hero Video instance, ⌘V — paste lands after the selection; classes and CMS bindings carry over). API note: `move_element` refuses component-instance anchors — reorder relative to static blocks instead (the `.Section.homenews` and `.Section.stories` blocks were the anchors here).

**Fixed-header offset (seasonsScroll 1.0.1, 17 Sep 2026).** Home has a fixed announcement bar + nav (`.nav-main`, 118px on desktop) that covered the hero copy and the top of the cards. The script now measures the fixed header (any `position:fixed` bar at the top of the viewport, ≥60% wide and under half the viewport tall; overlays with opacity 0 or `pointer-events:none` are ignored) and sets `--ssc-nav` on the section, or takes a manual `data-nav-offset="118"` attribute instead. The CSS derives everything from it: the hero copy starts `--ssc-nav + 56px` down (40px on phones, 32px on short viewports), `--ssc-card-h` is 86% of the frame *below* the header, slots and paddles are centred in that frame, and the hero state slides the card up by half the header while scaling by `viewport height ÷ card height` (set by the script as `--ssc-hero-scale`), so the full-bleed image still covers the whole viewport behind the translucent nav (with a slightly wider crop). A ResizeObserver on the header re-runs the layout if its height changes (announcement bar closed). With no fixed header the numbers are identical to before. The prototype's inline seasons CSS in `index.html` carries the same rules (the seasons block predates the single-source split, so `head.html` and `index.html` must be edited together).

## Browser bar tint (browserTint 1.0.0, 17 Sep 2026)

Adam wanted iOS Safari's bottom bar to read as part of the page, the way it does on apple.com. Safari can't be made transparent; it tints its tab bar from `<meta name="theme-color">` or, failing that, from the body background (`#f8f8f8` on this site, hence the light bar under the dark hero). Apple's page simply has a body colour that matches its top section. Ours can't (Brodie Experience is transparent over the light body, News and Locations are light, the rest dark), so `webflow/browser-tint.js` keeps `theme-color` in step with the section touching the bar: on every scroll frame it takes the element under the bar's edge (bottom edge on iOS Safari, top edge elsewhere, since Android Chrome's bar is at the top), walks up to the first opaque background colour, treats media (video, images, `.w-background-video`) as black, and falls back to the body colour. Safari animates the tint change itself. Built by `build-hosted.mjs` (plain-JS entry), applied as a hosted script to Home; the static `<meta name="theme-color" content="#000000">` in Home's head gives the first paint the right colour. Safe to apply site-wide with `add_site_script` (nothing page-specific in it).
